# 知衡 App：VS Code 运行与手机调试指南

适用项目：`E:\new项目\frontend`  
适用系统：Windows，本文终端使用 PowerShell。  
核对日期：2026 年 10 月 19 日。

## 1. 先明确：你现在应该怎么运行

**可以使用 VS Code 开发和运行这个项目。当前版本统一连接真实后端，请先准备数据库并启动 Java 后端，再启动前端，在电脑浏览器里完成注册和基础操作。**

当前前端使用 **Vue 3 + TypeScript + uni-app**，后端使用 Java。你可以按下面四个阶段操作：

| 阶段           | 你会看到什么                       | 需要什么                                            |
| -------------- | ---------------------------------- | --------------------------------------------------- |
| 电脑预览       | 浏览器里的手机界面，可以点击和操作 | VS Code、Node.js、Java 后端与 MySQL                 |
| 前后端联调     | 用真实账号保存、读取后端数据       | 前端 + Java 后端 + MySQL                            |
| 手机浏览器预览 | 手机打开电脑上的预览地址           | 手机和电脑在同一局域网                              |
| 手机安装版     | 手机桌面上的独立 App               | HBuilderX 或目标平台工具、AppID、签名配置和真机验证 |

浏览器预览使用的就是本项目的页面代码。正式安装包还涉及目标平台的运行环境、权限、图标和签名；**运行 `npm run dev:h5` 不会生成 APK 或鸿蒙安装包**。uni-app 官方也说明，CLI 项目可在其他编辑器开发，App 真机调试和发布需要配合平台工具。[uni-app 官方 CLI 说明](https://uniapp.dcloud.net.cn/quickstart-cli.html)

**本机当前已经安装了 Node.js 和前端依赖。你可以先直接执行第 4 节的启动命令；只有换电脑或缺少依赖时，才需要补做安装步骤。**

## 2. 第一次使用，需要准备哪些软件

### 2.1 VS Code

安装并打开 VS Code 即可。无需先安装 Android Studio 或手机模拟器，电脑浏览器预览就能开始开发。

### 2.2 Node.js

Node.js 用来运行前端的编译和开发服务，安装时会同时提供 npm。

本项目已使用 **Node.js 22.13.1** 编译验证。换电脑时可以先使用 Node.js 22 系列，避免同时升级工程依赖。

打开 VS Code，选择顶部菜单 **终端 → 新建终端**，执行：

```powershell
node --version
npm.cmd --version
```

能够输出版本号，说明基本环境已经就绪。

如果提示“无法识别 node”，先安装 Node.js，再**完全退出并重新打开 VS Code**，让新终端重新读取环境变量。

本文使用 `npm.cmd`，它是 Windows 下 npm 的命令入口，作用与常见教程中的 `npm` 相同，也能避开 PowerShell 阻止执行 `npm.ps1` 的情况。无需为此关闭系统执行策略。

### 2.3 推荐扩展，可选

在左侧“扩展”中搜索并安装：

- **Vue - Official**：Vue 页面提示、检查和跳转。
- **Prettier - Code formatter**：代码排版。

如果已经安装 Vue 2 常用的 Vetur，可以在本工作区停用它，避免与 Vue - Official 重复处理 Vue 文件。

这些扩展用于辅助写代码。项目能否启动，主要取决于 Node.js、依赖和启动命令。

## 3. 在 VS Code 中打开正确的文件夹

1. 点击 **文件 → 打开文件夹**。
2. 选择 `E:\new项目\frontend`。
3. 左侧文件列表中，应直接看到 `package.json`、`src`、`vite.config.ts`。
4. 点击 **终端 → 新建终端**。

如果你打开的是整个 `E:\new项目`，也可以，只需要先在终端进入前端目录：

```powershell
Set-Location -LiteralPath 'E:\new项目\frontend'
```

检查当前目录：

```powershell
Get-Location
```

结果应该是 `E:\new项目\frontend`。后续前端命令都在这个目录运行。

**不要直接双击 `index.html`，也不要用 Live Server 或“Run Code”按钮运行 Vue 页面。这个项目需要由 uni-app / Vite 编译启动。**

## 4. 启动前端开发服务

本节负责启动前端。首次运行请同时完成 [第 6 节的数据库和 Java 后端配置](#6-连接真实-java-后端)，保持前后端两个终端运行。

### 4.1 安装依赖：第一次或换电脑时执行

如果前端目录里已经有可用的 `node_modules`，可以跳过这一步。

```powershell
Set-Location -LiteralPath 'E:\new项目\frontend'
npm.cmd ci
```

工程提供了 `package-lock.json`，`ci` 会按锁定版本安装依赖。安装期间等待终端结束，不要同时启动另一份安装任务。成功后会生成 `node_modules`。

### 4.2 启动开发服务

```powershell
npm.cmd run dev:h5
```

看到编译完成和本地访问地址后，打开：

[http://localhost:5173](http://localhost:5173)

项目固定使用 `5173` 端口；启动时如果端口已被占用，会明确报错。

启动服务后，**保留这个终端运行**。它一直显示日志、不返回输入提示，是正常现象。

### 4.3 首次进入是什么状态

当前版本直接使用后端接口。首次进入尚未登录，会显示登录或注册入口；需要账号的页面会引导登录。

- 新账号没有预置的生活记录、计划或趋势数值，需要自己新增。
- 记录和计划通过后端保存到数据库，再次读取时仍以接口结果为准。
- 后端未运行、数据库连接失败或接口报错时，页面会提示错误。
- 本地注册无需邮箱 SMTP，验证码从运行 Java 后端的终端复制，详见 [第 6.5 节](#65-本地开发注册从后端控制台获取验证码)。
- AI 功能需要另行配置模型和用途授权；前后端启动后可以先使用手动记录与计划。

### 4.4 用电脑模拟手机尺寸

以 Chrome / Edge 为例：

1. 浏览器打开预览地址。
2. 按 `F12` 打开开发者工具。
3. 按 `Ctrl + Shift + M` 切换设备工具栏。
4. 选择一个手机尺寸，或手动设置为约 `390 × 844`。
5. 刷新页面，查看完整布局和底部导航。

项目在宽屏上也会限制主体宽度，方便直接检查手机界面。设备工具栏能模拟尺寸和触摸操作，系统通知、文件保存等手机能力仍需要真机检查。

### 4.5 修改代码和停止服务

修改 `src` 中的页面或样式后按 `Ctrl + S`，浏览器通常会自动更新。修改 `.env.local`、依赖或启动配置后，需要重启开发服务。

停止时，点击运行服务的终端，按 **Ctrl + C**。之后再次执行 `npm.cmd run dev:h5` 即可重新启动。

## 6. 连接真实 Java 后端

**当前页面统一使用真实后端，应在首次使用前完成本节。** 前端服务和 Java 后端是两个独立进程，需要分别保持运行；建议先启动 MySQL 和后端，再启动第 4 节的前端服务。

### 6.1 准备数据库和后端环境

后端需要 JDK 21、Maven 3.9 和 MySQL 8.0.29 或更高兼容版本。

先在数据库工具中，以 UTF-8 打开并执行：

```text
E:\new项目\database\zhiheng_full.sql
```

脚本创建 `zhiheng` 数据库和表，适合第一次初始化空库。已有同名业务表时，不要直接重复执行整份建库脚本。脚本不会自动创建测试账号或默认管理员密码。

### 6.2 在第二个终端启动后端

保持前端终端运行，在 VS Code 终端区域点击 **+**，新建一个 PowerShell 终端：

```powershell
Set-Location -LiteralPath 'E:\new项目\backend'

$env:ZH_DB_URL = 'jdbc:mysql://127.0.0.1:3306/zhiheng?useUnicode=true&characterEncoding=UTF-8&serverTimezone=UTC&connectionTimeZone=UTC&forceConnectionTimeZoneToSession=true'
$env:ZH_DB_USERNAME = '填写你的数据库账号'
$env:ZH_DB_PASSWORD = '填写你的数据库密码'
$env:ZH_ENVIRONMENT = 'DEV'

mvn -s .mvn/settings.xml clean package
```

将账号、密码替换为你自己的值。编译成功后，在**同一个终端**执行：

```powershell
java -jar target/zhiheng-backend-1.0-SNAPSHOT.jar --spring.profiles.active=local
```

以上命令显式选择 `local` profile；未指定 profile 时，工程默认也使用 `local`。本地开发保持 `ZH_ENVIRONMENT=DEV`。

这些 `$env:` 配置只对当前终端及其子进程生效。关闭这个终端后，下次要重新设置，或者通过自己的开发环境配置管理。后端不会自动读取 `backend/.env.example`。

打开下面的地址检查后端是否可用：

[http://127.0.0.1:8080/api/v1/health](http://127.0.0.1:8080/api/v1/health)

应看到 JSON 响应，且 `code` 为 `OK`。数据库连接失败等启动错误，先看后端终端的日志。

### 6.3 前端使用默认代理，最省事

当前开发配置已经把浏览器请求的 `/api` 转发到：

```text
http://127.0.0.1:8080
```

前后端都在这台电脑运行、后端端口为 `8080` 时，可以不创建额外配置文件。

如果需要显式写出配置，可在 `frontend` 根目录新建 `.env.local`，内容如下：

```dotenv
VITE_API_BASE_URL=
VITE_PROXY_TARGET=http://127.0.0.1:8080
VITE_PREVIEW_PLATFORM=ANDROID
```

这里第一项故意留空，表示浏览器通过当前开发服务的 `/api` 代理访问后端。`VITE_PREVIEW_PLATFORM` 用于浏览器联调时模拟移动端安装身份，不表示浏览器本身变成了 Android。

创建或修改环境文件后，停止前端服务，再重新运行：

```powershell
npm.cmd run dev:h5
```

### 6.4 从 App 界面连接账号

首次进入时点击页面上的 **登录 / 注册**；也可从 **我的 → 设置 → 账号管理 → 登录 / 注册** 进入。已有账号使用邮箱和密码登录；没有账号时按第 6.5 节注册。

在“服务器基础地址”中：

- **浏览器开发预览**：留空并保存，使用上述开发代理。
- **需要直接访问独立后端**：填写服务器根地址，例如 `http://192.168.1.10:8080`。
- **不要在根地址后再加 `/api` 或 `/api/v1`**，代码会自动拼接接口路径。

在界面中保存过非空服务器地址后，该非敏感设置会保留，并优先于环境变量。换环境时，记得检查这里，避免一直连接旧服务器。恢复开发代理时，也要确认 `.env.local` 中的 `VITE_API_BASE_URL` 为空，并重启开发服务。修改服务器会清除当前本地登录状态。

本版登录令牌只保存在本次进程内存中，浏览器整页刷新或重启 App 后，需要重新登录。

### 6.5 本地开发注册：从后端控制台获取验证码

当前数据库没有默认用户，也没有通用账号密码。按第 6.2 节启动的 `local + DEV` 环境，默认采用 `CONSOLE` 方式发送验证码，**不需要配置 SMTP 邮箱服务**。

按顺序操作：

1. 确认 Java 后端和前端终端都在运行，后端健康接口返回 `OK`。
2. 在 App 登录页面切换到 **注册**。
3. 填写邮箱地址、至少 12 位的密码。
4. 点击 **获取验证码**。
5. 切回 VS Code 中**运行 Java 后端的那个终端**，找到带有 `[LOCAL-VERIFICATION]` 的最新日志。它包含 `purpose=REGISTER`、`destination=你填写的邮箱` 和 `code=六位数字`。
6. 将 `code=` 后面的六位数字复制到前端的“邮箱验证码”输入框。不要从浏览器的 F12 控制台寻找，也不要把整行日志复制进去；如果重新获取了验证码，使用最新一次生成的值。
7. 点击 **阅读完整说明**，阅读由真实后端接口提供的本地服务说明。
8. 勾选“我已阅读并同意当前版本服务说明”和“我确认已年满 18 周岁”。
9. 点击 **创建账号**，以页面返回结果为准；若请求失败，按提示处理后再提交。

本地服务说明由 `/api/v1/development/policies/service` 返回 JSON 并在前端渲染，默认版本是 `local-service-v1`。该说明接口仅在 `local + DEV` 环境开放；注册同意与年满 18 周岁的确认仍然保留。

**默认本地配置已提供注册专用开关替代，不需要修改数据库种子里的 `auth.registration_enabled`。** 它只在 `local` profile 与 `DEV` 环境同时成立时生效，也不会改写数据库中的开关。显式设置 `$env:ZH_REGISTRATION_ENABLED = 'false'` 仍会禁止注册；修改环境变量后需要重启 Java 后端。

如果你之前手动设置过其他 profile、`ZH_ENVIRONMENT` 或 `ZH_VERIFICATION_DELIVERY`，以实际启动配置为准。需要切回本地控制台验证码时，在启动后端的终端中设置：

```powershell
$env:ZH_ENVIRONMENT = 'DEV'
$env:ZH_VERIFICATION_DELIVERY = 'CONSOLE'
$env:ZH_REGISTRATION_ENABLED = 'true'
java -jar target/zhiheng-backend-1.0-SNAPSHOT.jar --spring.profiles.active=local
```

先停止旧后端，再在其工作目录执行以上命令；此前配置的数据库环境变量也需要在同一终端保留。验证码由后端生成、校验并处理有效期，不会直接在前端返回验证码值。

非 `local + DEV` 环境使用 `ZH_VERIFICATION_DELIVERY=SMTP`，并配置真实邮件服务、部署注册开关、对应环境的数据库注册配置及正式 HTTPS 服务说明。**生产 `prod` 环境禁止 `CONSOLE`**，本地便利配置不能作为正式发布配置使用。完整参数见 [后端配置说明](../backend/README.md)。

| 提示或现象             | 含义与处理                                                                             |
| ---------------------- | -------------------------------------------------------------------------------------- |
| 点击获取后没有邮箱邮件 | 本地默认在 Java 后端终端输出验证码，不发送邮件；查看 `[LOCAL-VERIFICATION]` 日志       |
| `MAIL_NOT_CONFIGURED`  | 当前使用了 `SMTP` 方式但邮件配置不完整；本地核对 profile 与发送方式，其他环境补齐 SMTP |
| 注册未开放             | 检查是否显式关闭 `ZH_REGISTRATION_ENABLED`；非本地还需检查对应环境的数据库注册开关     |
| 服务说明尚未提供       | 本地核对后端是否为 `local + DEV` 并读取配置成功；其他环境配置当前版本的真实 HTTPS 文档 |
| 验证码无效或过期       | 核对邮箱与用途，重新获取后使用后端日志中最新的六位数字                                 |
| 登录后又回到登录页     | 检查是否整页刷新、令牌失效或切换了服务器                                               |
| 登录后没有记录         | 新账号初始为空，需要自行新增记录和计划                                                 |

### 6.6 AI 功能需要额外配置

真实 AI 不会因为前端启动成功就自动可用。它还需要：

1. 后端配置模型服务地址、密钥和模型名称。
2. 开启当前环境中需要演示的 AI 功能开关。
3. 发布 AI 用途说明，并由用户在“用途授权”中确认。

按后端 README 的“AI 服务”部分配置。**模型密钥放在后端环境变量中，不要放进前端 `.env`、Vue 页面或公开代码。** AI 不可用时，仍可以测试手动记录和计划等基础流程。

## 7. 用手机浏览器预览

这一节让手机访问电脑上的网页预览，**不需要安装 APK**。

### 7.1 确认网络

手机和电脑连接同一个可互相访问的局域网。部分校园 Wi-Fi 有设备隔离，即使 Wi-Fi 名称相同，也可能无法互访。

前端开发服务已配置为监听 `0.0.0.0`，启动命令仍然是：

```powershell
npm.cmd run dev:h5
```

### 7.2 查电脑的局域网地址

在一个空闲终端执行：

```powershell
ipconfig
```

找到当前使用的 Wi-Fi 或以太网适配器下的“IPv4 地址”，例如 `192.168.1.10`。不要选未使用的虚拟网卡地址。

### 7.3 手机打开地址

假设电脑地址是 `192.168.1.10`，手机浏览器输入：

```text
http://192.168.1.10:5173
```

用你查到的真实地址替换示例地址。手机中的 `localhost` 指向手机自己，不能用它访问电脑。

### 7.4 手机浏览器怎样连接后端

如果使用第 6.3 节的**空基础地址 + 开发代理**配置，手机发出的 `/api` 请求仍会由电脑上的开发服务转发到后端 `8080`，无需在手机里填写 `127.0.0.1:8080`。

若此前在该手机的“设置”中保存过服务器地址，先清空并保存，恢复开发代理。

如果采用直接访问后端的方式，就填写 `http://电脑局域网IP:8080`，并在后端跨域配置中允许手机页面的来源。后端返回的文件链接等地址也需要配置为手机可访问的 `ZH_PUBLIC_BASE_URL`。

### 7.5 打不开时检查什么

依次检查：

1. 电脑自己能否打开 `http://localhost:5173`。
2. 前端终端是否还在运行，是否编译报错。
3. 手机和电脑是否处于同一可互访局域网，IP 是否发生变化。
4. Windows 防火墙是否允许该开发服务在**当前可信的专用网络**中通信；按需要放行 `5173`，不要直接关闭整个防火墙。
5. 校园网是否限制设备互访；必要时换到你能控制的路由器网络。

手机浏览器测试适合验证触屏操作、布局和基础联调。系统通知、原生文件访问和后台执行仍需对应安装版验证。

| 命令                     | 用途                                   |
| ------------------------ | -------------------------------------- |
| `npm.cmd ci`             | 按锁定版本安装依赖；首次或换电脑时使用 |
| `npm.cmd run dev:h5`     | 启动浏览器开发预览，端口 `5173`        |
| `npm.cmd run dev`        | 与 `dev:h5` 相同                       |
| `npm.cmd run type-check` | 检查 TypeScript 和 Vue 类型问题        |
| `npm.cmd test`           | 运行前端自动化测试                     |
| `npm.cmd run build:h5`   | 生成网页发布文件                       |
| `npm.cmd run build:app`  | 编译 Android / iOS App 打包所用资源    |
| `npm.cmd run format`     | 按工程规则格式化源码                   |
| `Ctrl + C`               | 在当前终端停止开发服务                 |

`build:h5` 输出在 `dist/build/h5`，需要部署到 HTTP / HTTPS 静态服务后访问，不要直接双击构建目录中的 HTML。正式网页环境不包含本地开发代理，需要由网关转发 `/api`，或在构建前设置真实服务地址并配置跨域。

`build:app` 输出在 `dist/build/app`，是 App 所需的编译资源，**不是可直接安装的 APK / IPA**。平台安装包还需要第 9 节所述配置，并以实际构建与真机验证结果为准。

## 9. 以后怎样安装成真正的 App

先完成电脑浏览器预览和基础联调，再进入本节。

### 9.1 Android：VS Code 写代码，HBuilderX 做真机调试和打包

按 uni-app 当前官方工具流程操作：[App 真机运行说明](https://uniapp.dcloud.net.cn/tutorial/run/run-app.html)。

1. 安装带有 App 开发能力的 HBuilderX，并登录自己的 DCloud 账号。
2. 将**整个 `frontend` 工程目录**导入 HBuilderX，保留 CLI 项目的结构和依赖；不要只导入 `src` 后又混用两套编译器。
3. 在 `src/manifest.json` 的应用配置中，获取并填写你们自己的 DCloud AppID。当前工程的 `appid` 留空，未冒用现有应用标识。
4. 按需要配置应用名称、正式图标、包名和权限。
5. 手机开启开发者选项和 USB 调试，使用数据线连接电脑，并在手机上允许调试。
6. 在 HBuilderX 中选择运行到对应 Android 设备，首次按提示安装真机运行插件 / 运行基座。以实际设备与工具提示为准。
7. 在 VS Code 修改并保存源码，配合 HBuilderX 的运行日志验证真机表现。
8. 正式生成安装包时，走 HBuilderX 的 App 发行流程，按平台要求填写你们自己的签名证书等资料，完成后安装生成的 APK 验证。

正式发行所需的签名证书、包名和 DCloud AppID 是不同的配置。证书和密码由团队保管，后续更新版本需要保持一致。云打包会向打包服务提交相应项目资源，正式使用前按团队要求选择云打包或本地打包。

### 9.2 真机的服务地址必须单独确认

Android 安装版没有电脑 Vite 的 `/api` 开发代理。应在 App 的“我的 → 设置”中填写真机能访问的后端根地址，或者在构建前配置：

```dotenv
VITE_API_BASE_URL=https://你们实际部署的后端域名
```

这是待替换的示意值，不是可用服务。开发时使用局域网 HTTP 地址，还需要核对目标平台的明文网络策略；正式部署使用有效 HTTPS 服务。

不要在手机安装版填写 `http://localhost:8080` 或 `http://127.0.0.1:8080` 来连接电脑。后端的 `ZH_PUBLIC_BASE_URL` 也应保持为手机可访问的地址。

### 9.3 鸿蒙需要按目标系统配置

当前工程保留了 `app-harmony` 配置和编译入口，但**尚未完成鸿蒙签名、安装包和真机验证**。浏览器里能打开，不代表鸿蒙安装包已经可用。

如果目标是原生鸿蒙应用，应按 uni-app 的鸿蒙工具链说明配置 HBuilderX、DevEco Studio、SDK、应用标识和签名，再进行构建与真机测试。不要把 Android APK 当成已经适配的鸿蒙安装包。[uni-app 鸿蒙应用专题](https://uniapp.dcloud.net.cn/tutorial/harmony/intro.html)

### 9.4 iOS

iOS 安装、签名和调试有自己的证书与设备要求；本教程的 Windows 浏览器预览流程不等于已经具备 iOS 真机发布环境。设备确定后再按官方平台流程补齐。

## 10. 常见问题

### 10.1 提示找不到 package.json

通常是终端目录不对。执行：

```powershell
Set-Location -LiteralPath 'E:\new项目\frontend'
npm.cmd run dev:h5
```

### 10.2 提示“禁止运行脚本”或 npm.ps1 无法加载

使用 `npm.cmd` 代替 `npm`，例如：

```powershell
npm.cmd run dev:h5
```

也可以将 VS Code 终端切换成“命令提示符”。无需因此修改全局执行策略。

### 10.3 提示 uni 不是内部或外部命令

先确认依赖已经安装，并从 `package.json` 所在目录通过 `npm.cmd run dev:h5` 启动。不要尝试直接输入 `uni`，也不需要先安装全局 Vue CLI。

### 10.4 5173 被占用

如果是自己之前启动的同一工程，先在原终端按 `Ctrl + C`。不要结束不清楚用途的进程。

也可以临时换一个端口：

```powershell
npm.cmd run dev:h5 -- --port 5174
```

此时打开终端实际显示的地址，并将手机访问地址中的端口一起修改。通常仍建议使用默认 `5173`，方便复现教程。

### 10.5 依赖安装慢或下载失败

确认网络可用，保留终端错误信息。若是明确的下载错误，可以恢复网络后重新执行安装。先不要删除锁文件或使用 `--force` / `--legacy-peer-deps` 跳过兼容性检查。

### 10.6 页面正常，但真实账号连接失败

检查后端健康地址、App 设置里的基础地址和前端代理目标。打开浏览器开发者工具的 Network / 网络面板，查看请求地址及响应：

- 请求出现两次 `/api/v1`：服务器根地址填多了路径。
- `ERR_CONNECTION_REFUSED` 或代理连接失败：后端未运行、端口不对或地址不可达。
- `401`：检查登录状态和账号；必要时重新登录。
- `409`：常见于数据版本变化；重新读取最新内容后再操作。
- 跨域错误：浏览器直接访问了另一来源，核对后端允许来源，或恢复空地址使用开发代理。
- `FEATURE_NOT_ENABLED` / AI 配置错误：对应能力尚未开启或未完成真实配置。

### 10.7 改了 .env.local 为什么没生效

环境文件由开发服务启动时读取，先停止再重启。同时检查“我的 → 设置”里是否保存了旧服务器地址，它会优先使用。

### 10.8 登录后为什么还是没有记录

新账号初始没有生活记录、计划和趋势数值。先新增一条实际记录，再返回列表或趋势页读取；页面只显示当前账号可访问的后端数据。如果保存成功后仍无法看到，请检查筛选日期、服务器地址和网络面板中的接口响应。

## 11. 第一次运行照着做的最短清单

1. 在 VS Code 打开 `E:\new项目`，准备 JDK 21、Maven、MySQL 和 Node.js。
2. 首次使用时初始化 `database/zhiheng_full.sql`，配置自己的数据库账号密码。
3. 在一个终端进入 `backend`，按第 6.2 节编译并以 `local + DEV` 启动 Java 后端。
4. 打开后端健康接口，确认返回 `OK`，保留后端终端。
5. 新建另一个终端进入 `frontend`；缺少依赖时执行 `npm.cmd ci`。
6. 执行 `npm.cmd run dev:h5`，等待编译完成，打开 `http://localhost:5173`。
7. 切换“注册”，填写邮箱和密码，获取验证码后到 Java 后端终端复制六位数字。
8. 阅读完整服务说明，确认同意及年满 18 周岁，提交注册。
9. 新增自己的记录或计划，检查保存和再次读取结果。
10. 按 `F12`、`Ctrl + Shift + M` 查看手机尺寸；修改页面后保存，观察更新。
