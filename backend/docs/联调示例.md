# 知衡后端联调示例

所有例子均为接口字段示意。`<...>` 需要替换成你们真实保存的响应值，不能直接作为请求 ID；示例日期和业务内容按演示当天调整。完整字段在 `src/main/java/com/yqsoft/resource` 中定义，分页筛选字段见对应 controller。

## 1. 获取配置与注册

`GET /api/v1/configuration?platform=HARMONYOS&appVersion=0.1.0` 返回公开配置，前端据此显示能力入口。验证码：

```http
POST /api/v1/auth/verifications
Content-Type: application/json

{
  "destination": "填写测试邮箱",
  "channel": "EMAIL",
  "purpose": "REGISTER",
  "clientAudience": "MOBILE"
}
```

收到邮箱验证码后：

```json
{
  "account": "填写测试邮箱",
  "password": "填写12至128字符密码",
  "verificationId": "<verificationId>",
  "verificationCode": "<邮箱收到的验证码>",
  "adultConfirmed": true,
  "termsAccepted": true,
  "policyVersion": "<服务端配置且已展示的政策版本>",
  "installationKey": "<本次安装生成并保存的UUID>",
  "platform": "HARMONYOS",
  "timeZone": "Asia/Shanghai"
}
```

将上述 JSON 发到 `POST /api/v1/auth/register`。安全保存返回的 token、`userId`、`installationId` 和 `datasetEpoch`。以后普通业务带：

```http
Authorization: Bearer <accessToken>
Idempotency-Key: <每个逻辑操作唯一的UUID>
X-Data-Epoch: <datasetEpoch>
Content-Type: application/json
```

刷新请求是 `POST /api/v1/auth/refresh`，字段为 `refreshToken`、`installationKey`、`clientAudience`。客户端串行刷新，成功后原子保存新的一对 token；旧 refresh 重复使用会撤销整个会话族。

## 2. 新建生活记录

`POST /api/v1/records`：

```json
{
  "clientRecordId": "<UUID>",
  "recordType": "ACTIVITY",
  "startedAt": "2026-10-18T09:00:00.000Z",
  "endedAt": "2026-10-18T09:20:00.000Z",
  "recordTimeZone": "Asia/Shanghai",
  "recordLocalDate": "2026-10-18",
  "utcOffsetMinutes": 480,
  "notes": "晚饭前步行",
  "tagIds": [],
  "detail": {
    "detailType": "ACTIVITY",
    "activityType": "WALK",
    "actualDurationMinutes": 20,
    "intensity": "EASY"
  }
}
```

`recordType` 与 `detail.detailType` 必须一致。其他 detail：

```json
{"detailType":"SLEEP","sleepKind":"MAIN","restedLevel":4}
```

睡眠同时要求完整 `startedAt/endedAt`，服务端由真实区间计算时长。

```json
{"detailType":"MEAL","mealType":"LUNCH","description":"米饭、青菜和鸡蛋","mealContext":"CANTEEN"}
```

```json
{"detailType":"ENERGY","energyLevel":4,"contextCode":"STUDY","description":"下午学习后的主观状态"}
```

更新用 `PUT /records/{recordId}`，完整替换字段并额外传 `expectedRowVersion`；不允许修改事实类别。普通删除用 `DELETE` 和 `{"expectedRowVersion":"<当前版本>"}`，恢复用 `/restore`。普通删除保留可恢复正文；不可恢复的数据清理走隐私工单。

## 3. 手动计划先预览再生效

1. `POST /plans`：`title, planKind(DAY/WEEK/CUSTOM), timeZone, startDate, endDate, goalIds`。
2. `POST /plans/{planId}/versions`：`expectedPlanRowVersion, expectedActiveVersionId, changeReason, tasks`。首次生效前 `expectedActiveVersionId=null`。
3. 每个任务快照含 `draftTaskKey(UUID), title, taskType, scheduledStartAt, scheduledEndAt, plannedDurationMinutes, taskTimeZone, sortOrder`。新增任务 `taskId=null`；修改既有任务须保留其 `taskId` 和 `expectedTaskRowVersion`。
4. 调 `/versions/{versionId}/preview`，传 `expectedRowVersion, expectedActiveVersionId, effectiveFrom, affectedTaskIds, expectedTasks`，展示 `changes`、固定任务影响和提醒变化。
5. 用户确认后调 `/activate`，保留相同范围，增加 `expectedDataSeq=<preview.validation.checkedDataSeq>` 和 `userConfirmed=true`。

已封存版本不可直接修改；调整从现行版本创建新草稿。历史执行任务保持稳定 ID，不能通过新版本重写已经完成或跳过的历史。

`POST /tasks/{taskId}/complete` 只改变执行状态。记录真实睡眠/活动等事实须另建 `/records`，再通过 `PUT /tasks/{taskId}/record-links` 关联；不会因勾选任务就生成健康事实。

## 4. 文件上传

1. `POST /files/upload-intents`，传 `clientFileKey(UUID), purpose, originalName, mediaType, sizeBytes, sha256`。
2. 取返回的 `uploadUrl`，按 `requiredHeaders` 用 PUT 上传原始二进制内容。该 URL 本身带限时签名，不再额外包装 JSON。
3. `POST /files/{fileId}/complete`，传 `expectedRowVersion=<fileRowVersion>, uploadToken, sha256, sizeBytes`；核验成功才变为 `CLEAN`。
4. `POST /files/{fileId}/download-url`，可传 `{"disposition":"ATTACHMENT"}`。前端使用返回 URL；正文不暴露真实对象路径。

将 `CLEAN` 且用途匹配的文件 ID 附加到头像、记录或反馈。一次性 `uploadToken` 首次返回后应保存，重放回执不重新发放敏感凭据。

## 5. AI 草稿

先 `GET /me/consents` 读取目的、当前版本，使用当前公开政策按 `PUT /me/consents/AI_PROCESSING` 授权。首次授权请求：

```json
{
  "expectedRowVersion": "0",
  "decision": "GRANT",
  "policyVersion": "<currentPolicyVersions中AI_PROCESSING.version>",
  "deleteExisting": false
}
```

已有授权行时，`expectedRowVersion` 改用 items 内对应行的当前版本。配置模型且开启对应功能标识后：

```json
{
  "kind": "RECORD_EXTRACT",
  "clientRequestId": "<UUID>",
  "input": {
    "text": "今天中午12点吃了米饭、青菜和鸡蛋",
    "referenceInstant": "2026-10-18T05:00:00.000Z",
    "timeZone": "Asia/Shanghai",
    "clientRecordId": "<UUID>"
  }
}
```

发到 `POST /ai/runs`，按返回 `pollPath` 轮询，或用带 Authorization 的 SSE 连接读取 `/ai/runs/{runId}/events`。SSE 当前发送持久化运行状态，不提供逐 token 打字流。

运行成功后读取 draft。存在缺失或歧义时先引导用户补充，`PUT /ai/drafts/{draftId}/revisions` 新建修订，再 `/validate`。最后 `/apply` 必须携带当前 `expectedRowVersion, expectedDraftRevisionNo, expectedDataSeq, userConfirmed=true`；计划调整还需任务范围和固定任务确认。未经确认不会自动写入正式记录或生效计划。

## 6. 同步握手

1. `POST /sync/bootstrap`，传当前 `installationId,datasetEpoch,entityTypes`。支持 `PROFILE/PREFERENCE/GOAL/AVAILABILITY_RULE/AVAILABILITY_EXCEPTION/RECORD/RECORD_TAG/PLAN/PLAN_VERSION/TASK/REMINDER_RULE/NOTIFICATION`。
2. 为每个请求类型读取 `/sync/bootstrap/{bootstrapId}/entities`，直到 `hasMore=false`。客户端按 ID 和 rowVersion upsert。
3. 从 `snapshotFromSeq` 起读 `/sync/changes` 追增量；只确认实际拿到并已本地提交的 `nextAfterSeq`。
4. `POST /sync/ack`，提供 `bootstrapId,bootstrapCompleted=true` 完成初始化。未扫描完就确认会被拒绝。
5. 离线批次 `/sync/operations` 的每项使用稳定 `clientOperationId`，逐项处理 `APPLIED/REPLAYED/CONFLICT/REJECTED/NOT_PROCESSED`。

`DATA_EPOCH_CHANGED` 表示服务端已经清理旧代际，客户端清掉旧健康缓存并重新初始化；不要继续提交旧离线队列。

## 7. 隐私控制

`POST /privacy/requests/preview` 示例：

```json
{
  "type": "EXPORT",
  "scope": {
    "recordIds": ["<记录ID>"],
    "includeFiles": false,
    "includeAiContent": false,
    "includePlans": false
  },
  "format": "JSON"
}
```

预览返回 `requestId,rowVersion,manifestDigest,previewDataSeq,scopeSummary`。类型还支持 `DELETE_RECORDS/ERASE_HEALTH_DATA/DELETE_ACCOUNT`。展示范围后重新认证并确认：

导出中的 `includeFiles/includeAiContent/includePlans` 省略时均按 `false`。选择指定记录或日期等事实范围时，不自动捎带其他日期的统计、周回顾及档案偏好；明确开启的计划或 AI 内容按预览列出的模块范围另行导出。

```json
{
  "expectedRowVersion": "<预览rowVersion>",
  "manifestDigest": "<预览manifestDigest>",
  "expectedDataSeq": "<预览previewDataSeq>",
  "userConfirmed": true,
  "reauth": {"method":"PASSWORD","password":"<当前账号密码>"}
}
```

提交到 `/privacy/requests/{requestId}/confirm`，返回 `202` 后轮询工单。预览后目标发生变化时必须重新预览。清空健康数据会在真实清理结束后增加 `datasetEpoch`；注销会撤销会话，首次预览返回的 `receiptToken` 可用 `/privacy/receipts/status` 查询最小结果。导出下载另需重新认证，不允许绕过隐私入口用普通文件接口取出。

## 8. 常见状态码

| 状态 | 前端处理 |
| --- | --- |
| 401 | 会话失效或认证失败，重新认证 |
| 403 | audience、权限或用途授权不足，按明确错误码引导 |
| 404 | 资源不存在或不属于当前用户 |
| 409 | 版本、幂等、数据代际或预览冲突，重新读取再确认 |
| 410 | 初始化游标/租约等已过期，重新初始化 |
| 422 | 请求字段或跨字段校验失败 |
| 429 | 限流，等待后重试 |
| 503 | 外部能力未配置、功能未启用或供应商暂不可用 |
