# 知衡｜后端功能与接口规划

版本：V1.0（实施设计稿）  
日期：2026-10-16

客户端：uni-app＋Vue 3；服务端：Java 21＋Spring Boot；数据库：MySQL 8.4。配套文档：《知衡_数据库设计与实施规划.md》。本方案共 160 个接口，包含分期建设的接口，不代表已开发、接入或通过真机验证。

## 1. 功能范围与模块

知衡面向成年大学生，连接生活记录、时间安排、计划执行、AI 草稿与每周回顾。提供生活方式记录、日程辅助和有来源科普，不提供疾病诊断、处方、药量或疾病风险评分；数据不足保留空缺，不生成“健康分数”。

用一个 Java 应用、一个 MySQL 数据库，按账号、记录、计划、AI、内容、统计、提醒、隐私、同步、后台模块分包。数据库 outbox 作业承担统计失效、通知、文件清理及外部调用，不强制引入 Redis、MQ、向量库或 Python。文件私有保存，业务层只持 fileId。

P0 为账号、目标/时间、四类记录、版本化计划、AI 计划草稿、基础趋势、授权和数据控制、离线同步；P1 为自然语言记录、知识问答、每周回顾、附件、反馈、内容后台、经设备验证的系统提醒；P2 为第三方账号、语音、课程导入、手表和外部数据，默认关闭。完整 P0 比原产品稿的压缩排期复杂，按里程碑验收。

| 手机入口 | 后端能力 |
|---|---|
| 今日 | 业务日任务、下一任务、完成/跳过/延期、快速记录、提醒/同步状态 |
| 计划 | 日周任务、冲突预览、启用、历史版本、固定任务确认、循环模板 |
| 助手 | 必要信息补充、可取消生成、问答引用、记录/计划草稿、显式应用 |
| 趋势 | 睡眠、实际活动、任务执行、有效天数、原始证据、周报 |
| 我的 | 档案、目标、时间、偏好、提醒、授权、会话设备、导出删除、反馈 |

示例体验由客户端使用明确标注的模拟数据，不写真实账号。归属始终从认证主体取得，不接收客户端指定 userId。

## 2. 全局接口合同

手机前缀 /api/v1，后台 /api/admin/v1。目录手机路径省略前缀；/admin/... 实施时替换为后台前缀。设备也在 /api/v1，但使用独立 task-only 凭据。

所有 ID、rowVersion、versionNo、changeSeq、datasetEpoch 在 JSON 用十进制字符串，数据库仍整数；禁止用 JS Number。时间瞬时为 UTC ISO 8601 毫秒带 Z；日期 YYYY-MM-DD，时间 HH:mm，时区 IANA。JSON camelCase。

普通成功体为 {code:"OK",message:"成功",data:T,requestId:string,serverTime:Instant}。GET 200，创建 201，异步 202，成功无体删除/退出 204 不套 JSON。分页游标签名绑定账号、筛选、排序、epoch；稳定排序键＋id，不凭 updatedAt 推进同步。

| 权限 | 意义 |
|---|---|
| PUB | 公共但限流；认证不能泄露账号存在性 |
| U | 本人登录，同时核账号状态、securityVersion 和 session |
| U+AI | U＋AI_PROCESSING 当前授权 |
| U+EXT | U＋EXTERNAL_HEALTH 授权＋有效外部连接 |
| D:TASK | 独立设备 task.read/task.action，禁止读记录、对话和完整档案 |
| A:code | 后台会话＋具体权限码；管理员默认不能读取健康原文 |
| RECEIPT | 注销后仅查工单随机凭据，不能健康读写 |

### 2.1 写入、幂等与版本

目录写类：W＝普通业务写，必带 Idempotency-Key UUID、X-Data-Epoch；P＝非健康 epoch 的档案/授权/安装配置写，带幂等键和对象版本但不要求 epoch；B＝后台写，带幂等键与对象版本；A＝认证安全操作，独立于业务幂等；R＝读/临时签名/同步协议入口，不套普通业务幂等。版本修改必须 expectedRowVersion；计划额外 expectedActiveVersionId；AI 应用额外 expectedDraftRevisionNo。

同账号同 key 同标准化 payload 返回旧最小回执、replayed=true，不分配新 changeSeq；同 key 不同请求 409。HMAC 摘要包括 operationCode、业务字段及 epoch，不把健康原文放去重回执或通用日志。REST 和离线同操作用同 operationCode/service。去重保留 120 天，允许离线 30 天，超期要求重基。认证 token 不可套此重放规则。

MutationResult 为 resourceType、id、rowVersion、changeSeq、operationId、replayed。计划回执仅额外保存 planVersionId、affectedTaskIds 等 ID；完整内容后续读取。无所有权的对象 404；跨账号关系两层校验。

统一锁顺序 user_sync_clock → app_user → 业务/幂等行。先验 epoch、dataWriteFence、状态和本操作需要的授权，再写业务＋sync_change＋outbox＋committedSeq 并一起提交；重放不递增，一个事务可多事件连续序号。隐私流程不可反向锁。第三方/模型调用不持长事务；worker 回写前重锁 clock、复核 epoch/fence/该 purpose 的授权版本与源版本，不能仅靠 cancelled 标记。

补充重放返回规则：sync_operation只保存最小MutationResult。返回JobAccepted、InstallationView、PrivacyPreview等组合视图的写接口，重放先按旧回执定位资源，再重新鉴权加载当前状态，标replayed=true；它是当前视图，不是敏感旧正文快照。临时签名URL可在既定有效期内重新签发。一次性uploadToken、pairingToken、deviceCredential、receiptToken不写result_json，重放对应token/credential字段为null，并返回tokenUnavailable=true（boolean，可选扩展字段，未涉及secret时不出现）；需要原secret且已丢失时，在仍有本人权限下新key创建/轮换未消费意图。receipt必须在注销确认前保存，确认不重新签发。密码/验证码reauth不进入业务HMAC，执行前单独验证；重放已确认工单只取最小状态，不重新消费验证码。

## 4. 请求 DTO 字典

### 4.1 基础类型与必填规则

以下字段可映射为 Java record＋Bean Validation。“必”＝必须出现且非null；“选”＝可省略；没有显式“可null”的字段出现即不能null。创建的选填省略按默认值；PATCH 选填省略保留，显式null仅清空允许null字段；PUT全量替换，选填省略也覆盖为创建默认值。未知字段422，禁止mass assignment。数组不允许null元素。普通JSON≤256KiB，文件直传另限。

| 类型 | 约束 |
|---|---|
| Id/Seq/Version/Epoch | string，正十进制无前导零，1～20位；首次不存在版本按明确允许的"0"；空指针另标null |
| UUID | string，36字符标准UUID |
| Instant | string，UTC带Z、毫秒精度，拒绝无时区 |
| Date/LocalTime/TimeZone | 真实日期YYYY-MM-DD／HH:mm／IANA名称1～64 |
| Text(n) | string，trim后1～n字符，不用空串代替null |
| Decimal(a,b) | JSON有限number，最多a位整数、b位小数 |
| Enum(...) | 所列大写字符串，未知422 |
| IdSet(n) | 0～n个不重复Id |
| StringSet(n,m) | 最多n个不重复Text(m) |

查询日期含首尾，瞬时区间[from,to)，日期跨度默认最大366天。除声明外不允许客户端填owner、创建时间、状态、模型名、统计数值。

| 公共DTO | 字段 |
|---|---|
| PageQuery | cursor:选string≤1024，默认首屏；limit:选integer1～100默认20 |
| DateRangeQuery | from:必Date；to:必Date，from≤to、跨度≤366天 |
| VersionBody | expectedRowVersion:必Version |

### 6.2 关键事务边界

| 流程 | 同一短事务内 | 事务外／失败处理 |
|---|---|---|
| 注册/改密 | 锁验证码并一次消费；账号、最小档案/偏好/clock或改密码+securityVersion+撤session | 邮件投递异步/供应商调用不占事务；事务失败验证码不可被错误永久消费 |
| 记录创建/编辑 | 锁clock→user→去重/record；基础+唯一详情+标签；seq与失效outbox | 附件扫描先完成；统计worker可重建 |
| 任务状态 | 锁clock→user→task；版本/状态核验；task_event、任务状态、seq、撤提醒outbox | 不自动建活动记录；系统提醒撤销失败可重试但不能反向改任务 |
| 计划激活 | 锁clock→user→plan→版本/按id排序tasks；核active/范围/固定确认；分配新增taskId，封存快照、切active、事件/seq/outbox | 校验预览在事务外可算，提交时必须重验；模型不在事务内 |
| AI作业 | 接收事务只写run/必要快照/outbox；worker短事务认领；回写前重锁clock复核epoch/fence/相关授权和源版本 | 网络模型调用有超时/取消；输出JSON先结构/业务校验，不直接落事实 |
| AI应用 | 草稿revision及唯一applied约束＋对应record/plan服务＋seq/outbox同事务 | 应用过程中异常整笔回滚，不能草稿APPLIED但资源未生成 |
| 同步批处理 | 每个operation独立上述事务，成功项独立提交，失败项无半写 | 返回逐项结果；依赖失败的后项应NOT_PROCESSED或被明确拒绝 |
| 隐私预览 | 在一致性读/必要短锁下固定范围、dataSeq、摘要；注册preview与receiptHash | manifest私有且受限；预览自身不改变健康committedSeq，否则expectedDataSeq会自冲突 |
| 擦除/注销确认 | 固定清单/摘要/expectedDataSeq核验；fence和撤权/作业失效；登记受限最小删除台账 | 分批物理删，推进epoch，解除擦除fence；注销不再开账号；失败保留工单可恢复 |
| 外部导入 | 每批复核epoch、consentVersion、authorizationRevision，再按提供方稳定键去重入库 | 只有已核验来源数据可直接写，来源不明待确认；撤权后在途旧结果丢弃 |

计划中所有task锁按id排序降低死锁，死锁返回安全可重试错误，客户端复用原幂等键。outbox认领用租约/重试次数/nextAttemptAt；业务效果依赖幂等键，不把“数据库至少一次消费”等同外部投递恰一次。任何重试前重新检查删除栅栏、数据代际和对应授权。

### 6.3 AI 生命周期和流式交互

1. 接收请求验证授权、预算、输入大小；保存必要ID/版本、datasetEpoch和所需purpose版本；run进入QUEUED。
2. worker认领为RUNNING，读最小摘要、真实知识版本，事务外调用模型。模型输出不拥有业务写权限。
3. 结构化输出验证日期、时区、时长、任务数量、忙碌冲突、固定任务、历史范围、引用ID。缺信息为NEEDS_INPUT，不硬猜。
4. 回写前重验epoch/fence/相关授权/源版本；不满足则FAILED或CANCELLED，清理临时产物，不能保存擦除前结果。普通手动记录不受AI授权影响。
5. 成功只生成READY草稿/最终消息；应用必须单独确认。失效源产生409后重新生成/修订，不把最新task版本悄悄塞入旧稿。
6. SSE用Authorization头（或受控HttpOnly同源cookie），禁止accessToken放URL。每15～30秒心跳、单连接建议≤120秒；只给当前用户run。客户端用Last-Event-ID续传；若暂态片段已丢，RESET_REQUIRED后拉最终run/messages，不能伪造缺失文字。
7. uni-app目标运行环境不支持可靠SSE时，用GET run轮询：前10秒每2秒，随后3～5秒，停止于终态/页面离开；失败重试指数退避。cancel请求与供应商响应竞态，由回写检查决定最终状态，已SUCCEEDED不可撤回已保存事实（本就未自动写事实）。
8. worker配置供应商连接/读超时和总期限；超时不在前端无限转圈。失败保留用户输入与可重试原因，retry创建新run并计新预算，不重复应用旧草稿。

### 6.4 初始化、稳态同步和删除

- 短事务在clock锁下取得C0，登记bootstrapId、epoch、白名单、2小时INITIALIZING租约；之后按主键分页读当前实体，每条带rowVersion。不要用一个覆盖数千条数据的长数据库快照。
- 全量扫描期间发生编辑/删除：完成后从C0追增量，按rowVersion幂等应用。旧全量行不能覆盖增量的新行，DELETE墓碑要生效。分页扫描不代表“C0时间点精确快照”，而是配合变更追赶获得一致状态。
- 扫描所有白名单类型完成，追到该轮返回的高水位后才ack。服务端lastDeliveredSeq至少推进到C0，即使没有新增事件也允许ack C0；不能让客户端任意声称更大seq。
- INITIALIZING每页/changes/ack都核当前epoch和租约。成功ack后进入READY，后续稳态changes/ack按epoch、安装状态和保留窗检查，不继续要求那次2小时租约有效。
- nextAfterSeq只推进至实际返回最后事件；空页不擅自跳serverCommittedSeq。初始化的C0是服务端明确交付的起点，不同于空页任意跳游标。
- 保留日志默认90天；GC保护未过期初始化的C0。设备超过30天离线、游标早于retainedFromSeq或租约过期，410要求重新初始化。epoch改变始终409 DATA_EPOCH_CHANGED优先，旧租约和旧离线操作一并失效。
- 冲突时客户端保留“本地提案＋服务器当前版本”，提供重新编辑/采用服务器；不能自动最后写入覆盖用户历史。重基成功后用新clientOperationId表达新的用户决策，原失败操作不伪装成功。
- DELETE_ACCOUNT确认会撤session，receipt应在PREVIEW_READY阶段就一次性发给客户端并安全保存；确认使用既有receipt，不等首次注销响应才发。预览响应丢失时账号尚有效，可重取预览并轮换receiptHash；注销后只凭已保存receipt查询。
- 删除台账、PRIVACY_MANIFEST保存于受限命名空间，最小ID/范围摘要/生效代际/完成状态，不能被普通用户文件批删；另写独立只追加备份副本。备份恢复先重放删除/撤权台账并撤所有旧session/设备凭据，再开放访问，防止恢复已擦除内容。保留期是工程设计值，不等同合规结论或无限保留承诺。

## 8. 实施里程碑、分工与联调顺序

以下为有Vue/Java基础、2～3名学生持续投入的工程范围估算，不是两周承诺；考试、课业、从零学习、设备接入和演示完成度会改变周期。完整P0可按5～8周安排，P1再2～4周；P2在设备/审批核验后另估。可演示核心闭环先成，再分批补齐全部规划表/接口。

| 里程碑 | 建议投入/依赖 | 交付物 | 验收门槛 |
|---|---|---|---|
| M0 合同冻结 | 2～3天；共同 | 字段字典、状态图、错误码、初始迁移、OpenAPI骨架、示例数据规范 | 60表命名/关系一致；ID字符串；UTC/冻结业务日；账号模型和环境明确 |
| M1 真实记录闭环 | 5～7天；M0 | 注册登录、档案授权、四类记录、标签、文件基础、记录列表 | 真机/模拟器创建→重开仍存在；父详情原子；账号隔离；幂等/版本冲突 |
| M2 计划执行闭环 | 5～7天；M1 | 目标/时间、计划DRAFT/SEALED、预览启用、任务状态/关联/历史 | 延期taskId不变；完成/跳过历史不被覆盖；固定任务显式确认；旧提醒撤销意愿 |
| M3 AI草稿闭环 | 5～8天；M2 | 模型适配、run/取消/轮询、结构校验、草稿修订/显式应用 | 异常输出不落事实；一稿只应用一次；源过期409；撤权/擦除竞态不回写 |
| M4 趋势与隐私 | 5～7天；M1～M3 | daily_stat、口径说明、导出/固定清单删除/注销/receipt | 缺失不计0；去重统计；预览后新增阻断全擦；回执可在session失效后查询 |
| M5 离线与稳态联调 | 5～8天；M1～M4 | bootstrap/changes/ack、队列冲突、epoch重基、异常恢复 | 多设备不漏变更；90天GC/30天离线上限/2h租约可测试；重复重放无新seq |
| M6 P1增强与答辩 | 1～2周起；P0通过 | 知识审校后台、周报证据、反馈、RBAC、经验证系统提醒、验收记录和演示 | 权限矩阵/来源真实；只声明实测设备能力；演示数据标注；未完项可解释 |

并行安排：A负责手机页面、本地缓存/队列、交互与真机验证；B负责Java业务、数据库迁移/鉴权/同步；三人时C负责AI适配、知识资料、自动化验收和演示。两人时B承担AI，A与B共同核资料及关键状态测试。AI、隐私、同步涉及同一并发模型，必须共同评审，不能各做各的最后拼接。

建议前后端联调顺序：configuration/登录 → me/授权/安装 → 四类记录 → 目标/时间 → 手工计划草稿/预览/启用 → 任务状态/事实关联 → 统计真实数据 → AI run与草稿应用 → 隐私预览/导出/擦除 → 初始化与离线冲突 → P1后台/周报/提醒 → P2。每一阶段先跑真实保存读取，Mock仅用于前端空态/失败态，不能充当后端验收。

## 9. 配置、运维与待开发时锁定的参数

密钥、邮件账号、模型API key、JWT私钥、外部健康令牌加密密钥在环境或密钥服务，不写app_configuration.value_json、代码仓库或客户端包。数据库用户按迁移账号/运行账号分离；运行账号无DDL和整库导出权限。日志只记录requestId、操作码、资源ID、耗时、错误码；健康文本、prompt、token和邮箱明文默认不记录。外部URL抓取防SSRF，只允许受控HTTPS主机与跳转，不访问内网地址。

必须显式锁定的实施参数：目标手机系统/型号与可用SDK、Spring Boot稳定支持版本和依赖锁、邮件供应商/域名、模型与结构化输出能力/费用预算、实际对象存储与扫描实现、JWT和加密密钥轮换方式、数据保留/备份清除排程、课程/语音/手表审批能力。参数未锁定不影响P0手动记录/计划的数据建模；相关P2功能关闭。

最小权限后台：CONTENT_EDITOR只能编辑/提交；CONTENT_REVIEWER审核且不能自审；发布另有content.publish；SUPPORT仅反馈；SYSTEM_ADMIN管理配置/RBAC但无用户健康原文通行证。所有可能移除最后有效管理员的操作，先锁SYSTEM_ADMIN角色守卫行，再按固定顺序锁目标用户clock/app_user/业务对象，核剩余管理员；涉及多用户的安全操作按用户ID排序。普通用户业务从clock开始，不反向争用全局守卫。这样防止两个管理员并发互锁/互撤各自都以为“还剩一名”。

监控只统计匿名聚合：HTTP错误/时延、AI排队/超时/校验失败比例、outbox租约/重试、统计陈旧量、同步冲突/过期比例、隐私工单完成和失败量；不建设跨用户“健康排行榜”。性能指标先压测记录，演示前测目标机启动、保存和生成耗时，不编造“毫秒级/99.99%”承诺。

技术依据可查 [Spring 参数校验](https://spring.io/guides/gs/validating-form-input/)、[Spring Security授权](https://docs.spring.io/spring-security/reference/servlet/authorization/authorize-http-requests.html)、[MySQL行锁](https://dev.mysql.com/doc/refman/8.4/en/innodb-locks-set.html)。设备预留需核 [uni-app鸿蒙原生API](https://uniapp.dcloud.net.cn/tutorial/harmony/native-api.html) 和 [华为运动健康服务](https://developer.huawei.com/consumer/cn/hms/huaweihealth/)，这里的链接不能代替目标设备、系统版本及服务审批的实测确认。

字段补充：RecordCreate/Replace的ACTIVITY与SLEEP均要求endedAt；ProfileView.weekStartsOn映射week_start_day，PreferencePatch不跨写profile；notificationEnabled不再是偏好写字段，由consent、reminder_rule和OS权限共同决定。当前部署环境的后台配置不能从请求切换到其他环境。权限种子使用目录中content.read/content.edit/content.review/content.publish、user.read/user.security、rbac.read/rbac.manage、config.read/config.manage、audit.read、job.read/job.retry、feedback.read/feedback.manage，数据库permission_code保存这些稳定值。
