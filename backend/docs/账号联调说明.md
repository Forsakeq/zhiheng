# 账号、授权与档案联调

日期：2026-10-19。账号为成年用户邮箱，所有示例字段需换成测试人员自己的输入。

## 启动前配置

- 使用完整SQL建好的MySQL 8库；本次真实验证版本为8.0.29。后端不自动建默认管理员或测试账号。
- 默认 local profile + DEV 使用 CONSOLE 验证码，在启动Java后端的控制台打印 `[LOCAL-VERIFICATION] purpose=REGISTER destination=邮箱 code=六位数字`，前端复制六位数字即可；不会发送邮件。验证码随机生成并真实校验，HTTP响应不返回明文。
- 本地注册默认开启，使用 application-local.yml 中的本地专用开关替代数据库注册项，不改写种子配置；ZH_REGISTRATION_ENABLED=false 总开关始终优先。GET /configuration 的 authentication.registrationEnabled 与注册服务复用同一判定。
- 本地服务说明由 GET /api/v1/development/policies/service 实际提供；前端按当前版本渲染 sections，要求已阅读、同意和成年确认。其他环境不提供此端点。正式环境须设置真实HTTPS服务说明、版本及部署开关，并由受控运维将当前环境 app_configuration 的 auth.registration_enabled.booleanValue 改为true。
- SMTP 使用 ZH_VERIFICATION_DELIVERY=SMTP、spring.mail.* 与 ZH_MAIL_FROM；未配置返回503 MAIL_NOT_CONFIGURED。CONSOLE 仅允许 local + DEV，生产误配会拒绝启动。
- ZH_CONSENT_POLICY_VERSION为前端实际展示的不可变授权说明版本；每个purpose单独确认。未配置时不能伪造已发布说明。
- 加密/HMAC密钥需稳定，生产使用ZH_ENCRYPTION_KEY与ZH_HMAC_KEY，不能每次启动随机换密钥。

## 初次注册与登录

1. GET /api/v1/configuration?platform=ANDROID&appVersion=0.1.0：取得 authentication、localDevelopment 和当前服务说明。然后 POST /api/v1/auth/verifications：destination为邮箱，channel=EMAIL，purpose=REGISTER，clientAudience=MOBILE。返回verificationId、失效时间与邮箱掩码；本地 CONSOLE 从Java控制台复制验证码，SMTP 模式从邮箱读取。
2. POST /auth/register：携带邮箱、12～128字符密码、verificationId/verificationCode、成年和条款true、policyVersion、installationKey(UUID)、timeZone。首次安装还必须报实际platform=ANDROID/HARMONYOS/IOS，可放body或X-Client-Platform头。昵称可选。
3. POST /auth/login：clientAudience必须MOBILE或ADMIN；首次安装必须报真实platform；已有安装可省略。ADMIN必须WEB且账号有实际生效后台权限。
4. 每个refreshToken只消费一次。客户端要互斥串行刷新，先安全保存新access/refresh再释放等待请求。旧refresh再次使用撤销整family，重新登录；认证流程不走业务Idempotency-Key。
5. 普通手机业务仅接受MOBILE，后台仅ADMIN；/auth/logout、/auth/sessions自服务允许其原audience。ADMIN令牌不能作为读取手机健康原文的捷径。

邮箱归一化固定trim及小写，不删点号和+后缀，不自动合并第三方身份。邮箱只以HMAC查找、密文保存。密码为PBKDF2-SHA256自适应哈希，refresh/验证码只存摘要。验证码重发作废旧码、最多5次尝试，错码尝试计数会提交而不会因业务异常回滚。

## 档案、目标与时间

先GET /me取得profile/preference各自rowVersion。PATCH需要expectedRowVersion和至少一个业务字段；未传保持原值，bio/avatarFileId等明确允许null字段可清空；未知字段拒绝。timeZone和weekStartsOn属于profile，不跨写preference。修改历史时区不重归已有事实的业务日。

W写入需要Idempotency-Key UUID及X-Data-Epoch；档案、偏好、授权和安装元数据不强制epoch头但仍要业务幂等键。同key同业务内容重放旧回执，不同内容409。目标的definitionId必须来自字典；自定义用CUSTOM，不能写任意临床目标字典。targetValue和unit同时填写/同时null，按定义JSON Schema校验。

可用时间kind为BUSY/AVAILABLE/REST；REST在数据库映射RESERVED_REST。跨午夜明确endDayOffset=1，不用结束小于开始来猜。日期例外按一用户一日期聚合PUT，首次版本"0"，后续用返回rowVersion，slots最多24。DST缺失/重复时间分别422，日期例外可报startOffsetMinutes/endOffsetMinutes选择确切偏移。不会自动覆盖现行计划，应走计划草稿预览。

撤回AI授权立刻阻止后续调用和在途结果写回，手动记录仍可用；撤回本身不会假装删除历史。deleteExisting=true通过真实隐私预览返回privacyPreviewId，仍需用户另行重新认证确认。

## 测试

测试可注入VerificationSender实现/MockBean捕获验证码，禁止在生产HTTP响应或日志返回明文。AuthDeploymentSettingsTest 覆盖 local/default-local 与 DEV 联合守卫、混合prod profile拒绝CONSOLE、注册总开关优先、正式注册数据库开关以及真实说明地址；VerificationSenderConfigurationTest 实际捕获控制台输出并验证SMTP不打印验证码。AccessTokenServiceTest覆盖数值JWT日期、签名/算法/过期/issuer；AuthInterceptorTest覆盖会话撤权、后台与手机audience隔离和细权限；ProfilePatchContractTest验证null/省略语义及未知字段。

AuthProfileMySqlIntegrationTest仅在环境变量ZH_TEST_DB_URL明确指向已导入完整SQL的专用测试库时启用；测试事务回滚，不对生产库执行。配套ZH_TEST_DB_USERNAME/ZH_TEST_DB_PASSWORD由测试环境设置。它检验邮箱挑战、真实注册和逐代refresh复用撤权、目标归属、跨午夜例外。集成测试无真实邮件发送，使用测试sender。

单实例登录失败短期计数与数据库邮箱挑战频控均已实现；对公网仍需部署网关限制与监控，内存登录窗口重启会重置。P2第三方身份固定503，手表/外部健康能力不借安装capabilities自动开权限。

## 管理端

管理员接口在/api/admin/v1，所有方法有独立RequirePermission，默认无读健康原文权限。角色代码不复用，不能删除内建角色；SYSTEM_ADMIN固定角色行作为全局守卫，所有可能改变管理员有效性的写入先锁该行，再按用户ID排序锁clock与app_user。进入事务后再次校验后台会话和最新权限，防止等待期间撤权后继续写。

授予角色/权限不得超过操作者当前权限集合；因此SYSTEM_ADMIN不会凭角色名自动获得内容编辑/审核/发布能力。首次管理员与必要角色组合由受控运维建立，不开放默认管理员密码。SYSTEM_ADMIN分配不允许自动到期，交接后显式撤销，最后有效管理员受保护。

配置只允许当前部署中已有白名单键，按已保存schema执行MySQL JSON_SCHEMA_VALID；新增键、变更类型或公开范围通过受控迁移。密钥不入配置JSON。outbox人工重试仅RETRY/DEAD且属于允许的统计/提醒重算事件，核真实rowVersion、目标epoch/fence/授权；重试时计数归零开始新一轮有限尝试并写审计，不通用重放AI/隐私或删除事件。审计只保存字段名、资源ID和原因HMAC，不保管理员可能误填的健康原文。
